# Shared resource budget and backpressure

`shared.resource_budget` provides an injectable `ResourceBudgetManager`; application composition roots should reuse `GLOBAL_RESOURCE_BUDGET_MANAGER` so reservations are shared across applications. Per-run, application, and global profile values resolve from most specific to safe defaults. Global values remain hard cross-application caps; narrower profiles may lower a cap, while a higher per-run request cannot exceed the global ceiling. Resource leases are cooperative context managers and must be released promptly.

`BoundedResourceStage` runs independent stages with separate worker counts and bounded queues. A stage can forward its output into another stage; when the downstream queue fills, the current worker blocks and backpressure reaches upstream producers. Worker counts cannot exceed the resolved CPU thread/process or GPU job capacity and per-task demand. VRAM/RAM leases use megabytes. Lower integer priorities run first. `cancel_pending` stops ingress and discards pending items; `finish_active` lets active items finish before stopping. Running handlers should observe their cancellation token at their adapter boundary. `MemoryError` releases the original lease before one configured degraded attempt. Failures, backpressure, and degradation are exposed as metrics and through an optional error hook/logger.

Use `shared.retry_policy.external_api_backoff` for a capped exponential delay that can honor a server `Retry-After` hint. `shared.versioned_cache.BoundedVersionedCache` supplies an LRU bounded by both entry count and estimated bytes, explicit schema version keys, and clear/eviction behavior; inject `size_of` for large domain objects. Domain-specific applications own cached value schemas and should include only result-affecting inputs (not display thresholds) in the key.

The existing JobRuntime remains the lifecycle and priority source for whole jobs. Resource stages should be built with that job's run ID, cancellation event, priority, and resolved run profile so the shared budget constrains stages without creating a second whole-job scheduler. CLI adapters register `add_resource_budget_arguments` and resolve optional flags with `resolve_resource_budget_options`; GUI settings map to the same `ResourceBudgetOverride` contract. Both pass that profile to the shared manager.
